蜃灵统一渲染 — 音乐播放器 Bug 分析
========================================

【现象】
- 第一次点击播放偶尔正常
- 切换歌曲后再点击：有时无任何反应（控制台无消息），有时 404 报错，
  偶尔能播放成功（GD_API 有效时）

========================================
BUG 1：re-render 导致 state.btn 幽灵引用 + audio.src 残留 → 点击无反应
========================================

【因果链】
1. render.ts applyOrInsertCard（第27行）用 replaceWith(newHtml) 替换整张卡片 HTML，
   旧 <button> DOM 被移除，但 state.btn 仍指向旧元素。

2. 用户此时点击新按钮（DOM 中可见的那个），事件委托正常触发 onClick。
   进入 "同首歌" 判断（第115行）：state.keyword === keyword && audio.src 为 true
   （keyword 不变，audio.src 残留着上次的 URL——即使那个 URL 已 404 失效）。

3. sameBtn = state.btn === btn 为 false（旧幽灵 ≠ 新按钮），进入第129行 else 分支。
   - 如果 audio.paused 为 true（因为上次 URL 404 导致加载失败）：
     执行 audio.play()，试图播放一个已 404 的 src → 抛错 → catch 里设 btn 为 ▶。
     全程无 console 输出、无网络请求，用户看到"点了没反应"。
   - 如果 audio.paused 为 false（上次偶然成功了还在播）：
     仅设 btn 文字为 ⏸，不会重新加载 → 表面正常但实际可能在播旧歌。

4. 关键：因为走了 "同首歌" 分支就直接 return 了，不会重新 fetch 新 URL，
   所以用户无论怎么点都播不出来——除非 keyword 变了才会走 "新歌" 分支。

【佐证】
检查运行时状态时发现：
  audioPaused: false，但 stateBtnText: "▶"，statePlayId: 15
  → UI 与实际音频状态完全脱节，且经历了大量重试。

========================================
BUG 2：VK_API 返回的音乐 URL 失效（404）
========================================

控制台显示：
  GET http://ws.stream.qqmusic.qq.com/RS02000Pm1t82hY9RC.mp3?... 404 (Not Found)
  GET http://ws.stream.qqmusic.qq.com/RS020011x8D23CgKhh.mp3?... 404 (Not Found)

这些 URL 来自 VK_API (api.vkeys.cn) 的返回结果。原因：
- vkeys.cn 返回的 QQ 音乐 URL 包含临时 vkey，有效期很短（通常几分钟）
- 拿到 URL 后如果没立即播放，或者 URL 本身就已过期，audio 加载时就 404
- tryGD().catch(() => tryVK()) 的 fallback 链没有验证返回的 URL 是否真正可用

这个问题和 BUG 1 叠加后效果更差：
  - 第一次播放：走 "新歌" 路径 → tryGD 成功（或 tryVK 偶然拿到有效 URL）→ 播放成功
  - 歌曲播着播着 URL 过期 → audio 进入错误状态，但 audio.src 仍然是那个失效 URL
  - 用户再次点击 → 走 "同首歌" 路径 → 试图 play 那个失效 URL → 无声/报错
  - audio.src 残留 truthy 值，永远不会走 "新歌" 路径重新 fetch

========================================
【解决方案】
========================================

核心思路：
A. 不缓存 button DOM 引用，改为按 keyword 实时查 DOM
B. 在 "同首歌" 路径中检测 audio 错误状态，如果失败则重新 fetch

--- 具体修改 music-player.ts ---

1. 去掉 state.btn，改为实时查 DOM
   interface SlMusicState {
     keyword: string;
     playId: number;
     // 删除 btn
   }

   新增辅助函数：
   function findBtn(w: Window, keyword: string): HTMLButtonElement | null {
     if (!keyword) return null;
     return w.document.querySelector<HTMLButtonElement>(
       `.sl-music-btn[data-sl-music-keyword="${CSS.escape(keyword)}"]`
     );
   }

   audio 事件监听器改为实时查：
   audio.addEventListener('pause', () => {
     const s = w._slMusicState;
     if (!s?.keyword || !audio.src) return;
     const b = findBtn(w, s.keyword);
     if (b) b.textContent = '▶';
   });
   audio.addEventListener('play', () => {
     const s = w._slMusicState;
     if (!s?.keyword) return;
     const b = findBtn(w, s.keyword);
     if (b) b.textContent = '⏸';
   });

2. "同首歌" 分支增加 audio 错误/失效检测
   在第115行的 if (state.keyword === keyword && audio.src) 之后，增加：

   // 如果 audio 处于错误状态或 networkState 表示加载失败，视为新歌重新 fetch
   if (audio.error || audio.networkState === HTMLMediaElement.NETWORK_NO_SOURCE) {
     // 清除残留的失效 src，让后面走 "新歌" 路径
     audio.src = '';
     state.keyword = '';
     // 不 return，继续执行下面的 "新歌" 逻辑
   } else {
     // 原有的暂停/继续逻辑...
     ...
     return;
   }

3. （可选）在 "新歌" 路径 fetch 成功后，增加 audio 加载验证
   audio.src = url;
   // 监听一次 error 事件，如果加载失败则提示
   const onError = () => { ... };
   audio.addEventListener('error', onError, { once: true });

4. 增加 console.info 日志
   在 onClick 的关键分支处增加日志，方便后续排查：
   - 进入 "同首歌" 分支时 log
   - 进入 "新歌" 分支时 log
   - fetch 成功/失败时 log
   - audio.play() 成功/失败时 log
