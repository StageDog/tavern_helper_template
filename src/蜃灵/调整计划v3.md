## P3-1 · 涂鸦主题:`<list>` 多角色拆为独立块,参与 column-count 列流

### 问题

- `<list>` 解析出多个角色时,渲染端把所有角色塞在同一个 `.sl-block-list` 内的 `.sl-list-grid` 中,该 block 在涂鸦主题 `column-count: 3` 列流里是不可分割的整体
- 角色数较多时,该 block 变成很高的"竖条",其它 block(worldstate / currentTask 等)都比较短,导致列流失衡——视觉上像"一根特别长的竖条 + 几小段"
- 期望:每个角色独立成块,平等参与 column-count 三列流(像 worldstate / currentTask / database 那样)
- 解析失败回退场景(无 `.sl-list-grid`,只有整段 nl2br):保留旧的单块整段显示

### 约束

- **只改涂鸦主题** (`src/蜃灵/统一渲染/themes/graffiti-extra-css.ts`),不改 TS 渲染逻辑,不影响 news / bauhaus / gjsz
- 报纸主题保持现状(`.sl-block-list { column-span: all }` 是它的杂志风设计,不要动)

### 实现思路(纯 CSS)

利用 `:has()` 选择器区分"解析成功(有 `.sl-list-grid`)"和"回退(只有 `.sl-block-body`)"两种 DOM 形态:

**解析成功分支** `.sl-block-list:has(.sl-list-grid)`:

- `.sl-block-list { display: contents }` — 解构外层 block,让内部子节点直接进入 `.sl-memory-body` 的列流
- `.sl-block-list > .sl-block-title { display: none }` — 隐藏原"List"标题(每个角色块自带名字,不需要总标题)
- `.sl-list-grid { display: contents }` — 解构 grid,让 `.sl-list-char` 成为列流的直接成员
- `.sl-list-char` 升级为 `.sl-block` 等价物:
  - `break-inside: avoid` 让它整块不被列切
  - 复刻现有 `.sl-block` 的 `border` + `background` + `margin` + hover transition
  - `::before` `::after` 喷漆双竖线(参考现有 `.sl-block::before` / `::after` 写法,nth-child 4n 色轮换)
  - hover 倾斜 + 彩色阴影(对齐现有 `.sl-block:hover` 行为)
  - `.sl-list-char-name` 改为撞色头条 mini-block-title(背景填色 + `var(--gr-bg)` 文字 + display 字体 + uppercase + letter-spacing),nth-child 4n 颜色轮换
  - `.sl-list-char-items` 放进 mini-block 的 body 区域,补 `padding`/`font-size`/`line-height`

**回退分支** `.sl-block-list:not(:has(.sl-list-grid))`:

- 不写新规则,沿用现有 `.sl-block-list` 完整 block 行为(已通过通用 `.sl-block` 规则覆盖)

## P3-2 · 报纸主题:Database 提到 List 上方,消除列底空白

### 问题

- 报纸主题 `.sl-block-list { column-span: all }`,list 横跨三列
- 当前渲染顺序:worldstate → currentTask → plot → psychology → **list (column-span: all)** → **database**
- list 之后的 database 内容通常更短,在 list 横条下面又开新的三列流,只占一列,其它两列底部留大片空白

### 实现思路

**TS 端调换渲染顺序**(一行改动):让 database 渲染在 list 之前。

调整后:worldstate → currentTask → plot → psychology → **database** → **list (column-span: all)**
- 上半部分 5 个 block(含 database)由 column-count: 3 自动均衡铺排
- list 在最底部横跨全宽收尾,身后无残余 block,无空白

**为什么不用纯 CSS `order`**:`column-count` 容器不响应 `order`,改用 `flex-direction: column` 会丢掉报纸的多列杂志风,得不偿失。

**为什么不分主题渲染**:TS swap 是一行改动,对其它主题影响极小:
- 涂鸦(P3-1 改完后):database 块和 list 多角色块都在 column-count 流里,顺序差异在 auto-balance 下基本不可见
- bauhaus:`.sl-memory-body { display: block }` 单列竖排,database 在 list 之前观感正常
- gjsz:无 column-span,顺序变化无明显影响

引入主题感知的渲染分支不划算。

### 任务

- [ ] 在 `src/蜃灵/统一渲染/renderers/bottom-bar.ts` 的 `renderBottomBar` 函数中,定位 `.sl-memory-body` 内的渲染顺序(约 L296-L301)
- [ ] 将这两行交换:
  - **改前**:
    ```
    ${list ? renderListBlock(list) : ''}
    ${database ? `<div class="sl-block sl-block-database">...</div>` : ''}
    ```
  - **改后**:
    ```
    ${database ? `<div class="sl-block sl-block-database">...</div>` : ''}
    ${list ? renderListBlock(list) : ''}
    ```
- [ ] 验证报纸主题(news / news-deep):
  - database 出现在 list 上方
  - database 与前面 4 个 block 一起被 column-count: 3 均衡铺排
  - list 在最底部 column-span: all 收尾,身后无空白
- [ ] 视觉抽检其它主题:
  - graffiti(P3-1 修完后):列流均衡
  - bauhaus:单列堆叠,database → list 顺序正常
  - gjsz:同上

### Done 标准

- 报纸主题下 Database 渲染在 List 之前,列底大片空白消失
- 其它主题视觉无明显劣化

## P3-3 · 涂鸦主题:hover 竖线"延迟出现 + 长度短"修复

### 问题

- 涂鸦主题 `.sl-block::before / ::after` 双竖线(喷漆滴痕)的 `z-index: 0`,而 `.sl-block-title` 有撞色背景且 `z-index: 1`
- title bar 高度约 28-30px,**完全覆盖了静置态竖线**(14/18px,本来就在 title bar 高度范围内)
- hover 时 height 增到 30/38px,只露出 0~10px 进入 body 区域 — 视觉上"晚出现 + 短"
- 另外 `transition: height 0.45s` 比 hover 的 `transform 0.32s` 慢,加剧滞后感

### 历史背景

之前那次"竖线位置乱跑"修复(P2-4)是为了避免 multi-column 把负 top 的竖线漂到相邻列,所以从负 top 改成 `top: 0` 让竖线放在 block 内部。这次只调 `z-index` 和 `transition` 时长,**不动 `top` / `right` / 整体几何**,不会破坏那次修复的 multi-column 隔离。

### 实现思路

1. `z-index: 0` → `z-index: 2`,让竖线浮在 title bar 撞色背景之上(变成"始终可见的喷漆滴痕",符合设计本意)
2. `transition` 时长 `0.45s` → `0.32s` + 同款 `cubic-bezier(.25,.7,.3,1.1)`,与 hover transform/box-shadow 同步
3. hover height `30/38px` → `52/68px`(因为现在静置态就显形,hover 增量需要更明显才能体现"下滴"动感)

### 任务

- [ ] 在 `src/蜃灵/统一渲染/themes/graffiti-extra-css.ts` 中,修改 `& .sl-block::before, & .sl-block::after` 通用规则(约 L499-L509):
  - `z-index: 0` → `z-index: 2`
  - `transition: height 0.45s cubic-bezier(.4,0,.2,1), top 0.45s cubic-bezier(.4,0,.2,1);` → `transition: height 0.32s cubic-bezier(.25,.7,.3,1.1), top 0.32s cubic-bezier(.25,.7,.3,1.1);`
- [ ] 修改 hover 高度规则(约 L542-L543):
  - `.sl-block:hover::before { height: 30px }` → `52px`
  - `.sl-block:hover::after { height: 38px }` → `68px`
- [ ] 验证:
  - 静置状态双竖线完全显形于 title bar 撞色背景上,作为"喷漆滴痕"装饰
  - hover 时双竖线下伸,与 block 倾斜 + box-shadow 同时启动(无滞后感)
  - 双竖线 2px 宽,位于 `right: 18px / 26px`,不会盖到 title bar 文字(最长的 `WORLDSTATE` 也远到不了那里)
  - multi-column 三列下竖线不漂移到相邻列(继承之前 `top: 0` 内置的隔离)
- [ ] 与 P3-1 的协同(见公共注意点):如果 P3-1 中 `.sl-list-char::before / ::after` 是直接复制 `.sl-block::before / ::after` 的参数,确保用的是 P3-3 修正后的参数(z-index: 2、0.32s、52/68px),保持视觉一致

### Done 标准

- 涂鸦主题下静置态双竖线即可见(显示在 title bar 撞色背景上,作为常驻喷漆滴痕)
- hover 时双竖线下伸与其它 hover 效果(倾斜 + 彩色阴影)同时出现,无视觉滞后
- 长度变化明显("喷漆下滴"动感清晰)
- multi-column 三列布局下竖线不漂移到相邻列

## P3 公共注意点

- P3-1 / P3-2 / P3-3 三者关系:
  - P3-1 是纯 CSS(graffiti),P3-2 是 TS 一行 swap(bottom-bar),P3-3 是纯 CSS(graffiti)
  - **强烈建议顺序:P3-3 → P3-1 → P3-2**。原因:
    - P3-1 中新拆出的 `.sl-list-char` 要复刻 `.sl-block::before / ::after` 的双竖线参数。如果 P3-3 先做,P3-1 直接抄到的就是修正后的参数(z-index: 2、transition 0.32s、hover 52/68px),保持视觉一致;否则做完 P3-1 再做 P3-3,需要回头同步两个地方
    - P3-2 放最后,这样涂鸦主题的视觉测试(P3-3 + P3-1)已经稳定,不会在测试 P3-2 时被涂鸦主题的中间态误导
- P3-1 的 `:has()` 选择器在 `graffiti-extra-css.ts` 的 `&` 锚点下应该正常工作(`&` 会被构建脚本替换为根选择器,`:has` 跟在它后面是合法语法)。如打包后发现选择器失效,检查构建时是否被某个 CSS 处理器降级了 `:has` 支持
- P3-3 调 z-index 后,如果发现竖线在某些主题色组合下与 title 文字视觉冲突(比如黄色竖线 + 黄色 title 撞色),可以微调 `right` 位置或竖线颜色规则;但目前所有 title 撞色都用 `--gr-cyan / --gr-pink / --gr-yellow / --gr-purple / --gr-lime / --gr-text`,竖线 nth-child 配色一般不会与同 block 的 title 完全同色(轮换错开),低风险
